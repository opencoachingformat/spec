# Plan D — arc42 Architecture Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to execute this plan. Work one task at a time, dispatch a subagent per task, and stop at each review checkpoint. Do not batch tasks.

## Goal

Ship Plan D of 4 (the final plan) of the site redesign. Pull the ocf-validator's
**arc42 architecture docs** into the Astro site at build time and publish them
under **Build → Architecture**, with their Mermaid diagrams rendered.

The arc42 docs live in `opencoachingformat/ocf-validator` at `docs/arc42/*.md`
— 13 Markdown files: a `README.md` and twelve numbered sections
(`01-introduction-and-goals` … `12-glossary`). Exactly three of them
(`03-system-scope-context`, `06-runtime-view`, `10-quality-requirements`)
contain fenced ` ```mermaid ` code blocks; there is **no PlantUML** anywhere in
arc42.

A build step (`site/scripts/build-arc42.mjs`) fetches those 13 files from a
**pinned validator commit** via jsDelivr's GitHub-file CDN (the same
read-remote-at-build → write-`src/generated/` pattern as `build-adoc.mjs`
already uses for `error-codes.json`), renders each Markdown file to HTML with
`marked`, and — crucially — converts each fenced ` ```mermaid ` block into a
`<pre class="mermaid">…</pre>` element (instead of the default
`<pre><code class="language-mermaid">`), so that a small client-side module
script (`mermaid@11` ESM from jsDelivr) renders them **in the browser**. This
is the design's 2026-08-28 revision: **Mermaid renders client-side**;
`@mermaid-js/mermaid-cli`/`mmdc` is explicitly **not** used (it downloads a
headless Chromium and failed to install in this environment). PlantUML stays
build-time (Plan A), but arc42 has no PlantUML so this plan touches only Mermaid.

Two new Astro routes serve the docs: `build/architecture/index.astro` (an
overview + table of contents) and `build/architecture/[section].astro` (a
`getStaticPaths` template that renders each section's generated HTML via
`set:html`). The section pages include the client-side mermaid module script;
the Build hub gains an **Architecture** card linking `/build/architecture/`.

Plan D changes **no schema/validator code** — it consumes the arc42 Markdown at
a pinned commit. It adds one runtime-free dependency (`marked`) to the site.

3. Implement `site/src/lib/mermaid-marked.mjs` with the full contents below.
   `mermaidAwareMarked` configures a `marked` extension so a ` ```mermaid `
   fenced token renders to `<pre class="mermaid">` with the **raw** (unescaped)
   diagram source; every other token uses `marked`'s defaults. `buildArc42Index`
   is a pure filename → TOC transform (README pinned first, then numeric-prefix
   order; non-`.md` files dropped).
   ```js
   // Pure, offline-testable helpers for the arc42 build:
   //   - mermaidAwareMarked(markdown): Markdown -> HTML, but a ```mermaid fenced
   //     block becomes <pre class="mermaid">SOURCE</pre> (raw diagram source,
   //     NOT escaped, NOT wrapped in <code>) so mermaid@11 renders it in the
   //     browser. All other Markdown uses marked's defaults.
   //   - buildArc42Index(files): arc42 filenames -> sorted TOC entries.
   // No network, no filesystem, no side effects.

   import { marked, Marked } from 'marked';

   // A fresh Marked instance carrying a custom `code` renderer, so the global
   // `marked` singleton is never mutated (keeps other callers, e.g. tests,
   // isolated). marked passes fenced-code tokens to `renderer.code`; when the
   // info string is `mermaid` we emit a client-render <pre class="mermaid">
   // with the raw source; otherwise we defer to marked's built-in escaping.
   function makeMermaidMarked() {
     const instance = new Marked();
     instance.use({
       renderer: {
         code(codeOrToken, infoString) {
           // marked v5+ passes a token object; older signatures pass (code, lang).
           const token =
             typeof codeOrToken === 'object' && codeOrToken !== null
               ? codeOrToken
               : { text: codeOrToken, lang: infoString };
           const lang = (token.lang || '').trim().split(/\s+/)[0];
           if (lang === 'mermaid') {
             // Raw diagram source — mermaid parses it as-is. Do NOT HTML-escape.
             return `<pre class="mermaid">${token.text}</pre>\n`;
           }
           // Non-mermaid fence: fall back to marked's default escaped code block.
           return false;
         },
       },
     });
     return instance;
   }

   const mermaidMarked = makeMermaidMarked();

   export function mermaidAwareMarked(markdown) {
     return mermaidMarked.parse(markdown ?? '');
   }

   // "06-runtime-view.md" -> "6. Runtime View"; "README.md" -> "Overview".
   function titleFor(file) {
     if (/^readme\.md$/i.test(file)) return 'Overview';
     const base = file.replace(/\.md$/i, '');
     const m = base.match(/^(\d+)-(.+)$/);
     if (!m) {
       return base
         .split('-')
         .map((w) => w.charAt(0).toUpperCase() + w.slice(1))
         .join(' ');
     }
     const num = String(Number(m[1]));
     const words = m[2]
       .split('-')
       .map((w) =>
         ['and', 'of', 'the'].includes(w)
           ? w
           : w.charAt(0).toUpperCase() + w.slice(1)
       )
       .join(' ');
     return `${num}. ${words}`;
   }

   // Pure transform: arc42 filenames -> [{ file, slug, title }].
   // README first, then ascending numeric prefix. Non-.md files are dropped.
   export function buildArc42Index(files) {
     const entries = files
       .filter((file) => /\.md$/i.test(file))
       .map((file) => ({
         file,
         slug: file.replace(/\.md$/i, '').toLowerCase(),
         title: titleFor(file),
       }));

       if (Number.isNaN(an)) return 1;
       if (Number.isNaN(bn)) return -1;

     });
